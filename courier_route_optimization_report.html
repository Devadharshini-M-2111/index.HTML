Courier Parcel Delivery Route Optimization System

A graph-based delivery system that prioritizes parcels and calculates shortest routes from a warehouse using Dijkstra’s algorithm.

Student: DEVADHARSHINI M
Register Number: 711525BCS023

1. Abstract

Courier companies need to assign parcels and choose routes that reduce transportation distance and delivery time while considering parcel priority. This project represents a city road network as a weighted, undirected graph. Parcels are sorted by priority—URGENT, HIGH and NORMAL—and Dijkstra’s algorithm with a binary min-heap finds the shortest route from the Warehouse to each destination.

2. Objectives

  1. Model a city road network as a weighted undirected graph using adjacency lists.
  2. Dispatch parcels according to URGENT, HIGH and NORMAL priority.
  3. Find minimum-distance routes from the Warehouse using Dijkstra’s algorithm.
  4. Estimate delivery time from route distance and compare it with expected values.
  5. Analyse time and space complexity and discuss possible routing extensions.

3. Problem Statement

Input

  • A graph of locations and roads, with positive road distances in kilometres.
  • Parcels with an ID, destination, priority and assigned agent.
  • Warehouse as the starting point and assumed agent speed of 30 km/h.

Output

  • Priority-based parcel dispatch order.
  • Shortest route, distance and estimated time for each parcel.
  • Summary totals for distance and delivery time.
Objective: Minimise transportation distance and delivery time while serving higher-priority parcels first.

5. Algorithms Used

Priority Dispatch

Parcels are sorted so URGENT parcels are processed first, followed by HIGH and NORMAL parcels. The implemented report uses Python’s stable sort.

Priority sorting: O(n log n)Stable ordering

Dijkstra’s Shortest-Path Algorithm

  1. Set the Warehouse distance to zero and all other distances to infinity.
  2. Use a min-heap to select the location with the smallest tentative distance.
  3. Relax neighbouring roads when a shorter route is found.
  4. Stop when the destination is selected and reconstruct the route using predecessors.
DIJKSTRA(G, source, destination) set all distances to INF distance[source] = 0 push (0, source) into min-heap while heap is not empty: (d, u) = extract minimum skip stale heap entries if u is destination: stop for each neighbour v of u: if d + weight(u,v) < distance[v]: update distance[v] and predecessor[v] push updated pair into heap reconstruct and return the shortest path
O((V + E) log V)Dijkstra time complexity
O(V + E)Graph and auxiliary space

The submitted implementation is in Python 3. This page is an HTML presentation of the report, not a conversion of the Python algorithm into a live routing engine.

9. Advantages

  • Finds optimal shortest paths when road weights are non-negative.
  • Processes urgent parcels before lower-priority parcels.
  • Uses an efficient min-heap-based shortest-path algorithm.
  • Displays routes, distances and estimated delivery times clearly.
  • Can be extended to support capacity and deadline constraints.

10. Limitations

  • Each parcel is routed independently from the Warehouse.
  • Agent assignments are fixed rather than automatically optimised.
  • Capacity and delivery deadlines are not yet enforced.
  • Travel-time estimates assume 30 km/h and ignore traffic and service time.
  • The sample network is small and uses illustrative distances.

11. Future Enhancements

  1. Run Dijkstra once from the Warehouse to obtain distances to all destinations.
  2. Add parcel weights, vehicle capacities and delivery deadlines.
  3. Automatically assign parcels to agents and optimise multi-stop tours.
  4. Use real map data, one-way roads and live traffic information.
  5. Add a graphical map display and CSV/file-based input.

12. Conclusion

The Courier Parcel Delivery Route Optimization System models a road network as a weighted graph, sorts parcels by priority and calculates shortest delivery routes using Dijkstra’s algorithm. In the sample network, the four parcel routes are 10 km, 15 km, 6 km and 7 km, giving a combined independent-route total of 38 km and 76 minutes at the assumed speed. The report also explains that realistic multi-stop, capacity-constrained routing is more complex and may require dynamic programming, branch and bound or approximation methods.
